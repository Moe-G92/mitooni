## Account and lifecycle contracts

Identity stays separate from profile and authority. `/api/me` is unchanged identity-only. `/api/account` is runtime-validated as identity, membership, routing state and nullable profile. No fictitious name, plan, accommodation or measured level is projected. Nonmember/inactive identities receive access-required and no grants. A setup account lacking profile-write authority gets no enabled onboarding write. Learning/coach routes retain the Mo frame with an unavailable state; no simulated learning imports or invented entitlements are exposed.

Initial onboarding posts a full editable snapshot with expectedRevision 0; a normal profile change patches only allowed editable fields and the captured revision. UUID Idempotency-Key and captured X-Expected-User-Id accompany every write, with Authorization Bearer, credentials omitted, cache disabled and redirects rejected. Retries retain the exact operation body/key/revision. Structured backend code/requestId/fields are parsed; raw provider/server messages are not echoed. Revision-conflict UI retains the draft and offers an explicit discard-and-load action. Saved confirmation clears when a new edit or language choice makes it stale. Fields lock during a pending save, and an accepted ACK updates the draft without remounting away its confirmation.

Session ownership is subject plus epoch from token capture through refresh, send, response, canonical commit and draft mount. A change immediately purges the canonical cache/ref/error and hides private UI. Late work cannot commit under the next account, including a later session for the same subject. Historical idempotent replays cannot reduce canonical profile revision or restore an old locale; their current membership envelope still governs authority.

SDK sign-in, explicit refresh and sign-out operations are serialized. Local sign-out invalidates memory before awaiting the provider and writes a receiving-project tombstone. A delayed old sign-out finalizer cannot erase a newer deliberate sign-in. An unexpected foreign-subject event conservatively invalidates the account. A 15-second hung operation permanently quarantines that controller: no subsequent sign-in is dispatched into the still-mutating SDK; recovery requires reload into a fresh client. A rejected refresh/terminal401 expires the account; transient refresh/backend503 preserves the session for retry.

Both real and fixture AuthPorts prohibit persistent session rehydration. SDK options are persistSession:false and detectSessionInUrl:false; this credential-only slice requires deliberate sign-in after reload, then reloads the durable profile from the BFF. A scoped sign-out marker and token-free receiving-project BroadcastChannel propagate sign-out to open peer tabs. Sign-in in another tab does not switch or restore a peer's identity. If neither storage events nor a receiving channel can operate, account bootstrap fails closed. This is same-browser UI purge, not all-device token revocation.

Before any SDK factory/account fetch, worker migration inspects covering registrations and the controller. Only the exact same-origin root `/mockServiceWorker.js` registration is unregistered; unrelated non-covering workers and caches remain untouched. Unknown covering workers block. A retained known controller permits at most one sessionStorage-bounded reload, otherwise shows recovery. No generic CacheStorage deletion is performed: this source MSW worker has no app cache to migrate.

Registration/enrollment, phone OTP, social sign-in, recovery callbacks, persistent login, paid entitlements and provider AI remain unavailable in this slice. A verified shared-provider identity does not enroll itself in Mitooni. The synthetic membership issuer is local-only; no production signup outcome is claimed.
