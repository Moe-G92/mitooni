## Proposed smallest complete teaching loop

The durable learner workspace remains the authority. The model supplies customized teaching, never arbitrary writes or an independent curriculum.

1. Server selects an available source-grounded task for candidate track/objective/skill and pins source, content, assessment and journey revisions. It projects bounded candidate context and authorized teaching anchors.
2. Teach/elicit: actual provider generates a focused explanation/example and one comprehension/application check at a suitable level. Candidate answers; the next call receives that exact captured answer, rather than fabricating an answer or merely repeating the same generic lesson.
3. Feedback: for R/L use deterministic answer evidence plus the candidate's explanation; for Writing use exact response spans and task criteria; for Speaking use actual waveform and all four criteria. Feedback names the observed issue, evidence and an actionable revision. No band calculation or prototype scores.
4. Repair: preserve original attempt and append a revision/check response. Tutor changes explanation/example based on the observed error, explicitly asks candidate to try again and waits. Original and repaired evidence remain distinct; AI coaching exposure means supported practice.
5. Next: server computes eligible source-backed choices from objective prerequisites, observed work and candidate goals. Model chooses among these and explains its reasoning with evidence IDs. Server checks membership, pinned versions, evidence scope, current journey revision and target eligibility before the candidate accepts. A permitted choice is not mastery evidence.

Prefer one bounded Responses model invocation per teaching/feedback/planning turn initially: project anchors/snapshot/next options into the request, disable optional tools for that route and set SDK turns to one. This keeps the actual Agents SDK typed output/guarding without needless additional model requests. Existing scoped tools may remain for compatibility or later larger retrieval; enabling multi-turn tool loops requires reserving each possible request and its enlarged inputs before it can execute.

- Captured learner response: versioned text or answer map or recording reference. Normalize structured R/L selections to an unambiguous server-produced textual projection when reusing exact-span feedback. A transcript is auxiliary uncertain evidence, never replacement audio.
- Planner choice: step/content/version, objective, reason category and eligible evidence IDs. Backend constructs eligible choices; model proposes one; acceptance uses compare-and-swap journey revision. No arbitrary generated step IDs or model-written progress.
- Feedback evidence: criterion + source anchor + exact captured-work span, deterministic answer evidence, or audio evidence reference. Only committed, owner-scoped evidence can feed the next turn/planner.
- Speaking extension: allowlisted candidate/learning context and locale in SpeakingInput plus schema instruction; keep the four criterion contract and no-band assessment scope. A repair task references prior committed recording feedback and asks for a fresh recording, never edits the original.

Listening semantics: actual source audio with timed replay/exposure state is essential. Supported learning may expose an authorized transcript/segment after the listening attempt; exam practice keys/transcript remain private until allowed release. The tutor can explain a candidate's answer against source audio-derived anchors, but a transcript-only exercise must not be presented as a listening attempt.

Speaking semantics: parts 1/2/3 preserve their task instructions, preparation/recording constraints and source/version bindings. A short part rehearsal is not a full interview. All four criteria appear; insufficient evidence is criterion-specific. Pronunciation and temporal fluency require audio, not reading the transcript. Model timestamps stay estimated/unverified.

## Global money accounting design

Use one shared PostgreSQL budget/ledger across text, Speaking and any optional transcription/TTS path, scoped to the explicitly authorized project/run budget rather than user. Integer USD micro-units avoid float drift. No default funded allowance. Existing per-owner call/storage caps can remain additional abuse limits.

Atomic admission locks budget row and idempotent dispatch/reservation row; require settled + active reservations + requested conservative maximum <= approved cap. Record model, endpoint, price-table version, maximum billable input/output and permitted service tier. Preparation without external I/O can release a canceled reservation; record dispatch in the same durable handoff that marks spending possible.

Use explicit Standard tier to prevent project-default Fast cost surprises. Bound all input, output/reasoning, model requests and tools; reserve against conservative full uncached prices, including cache-write premiums where applicable. A token estimate with arbitrary slack is not a proven hard money cap. For audio, if a documented duration/token upper bound cannot be established, reserve against the model's entire advertised context at the highest input modality price plus maximum output, or fail closed. This may be conservative; refine only with independent proof. No automatic transcription/TTS chain in MVP.

Persist usage even when pedagogical/schema validation fails. Tutor stream should include response/model identifiers and usage before candidate release; worker passes a durable settlement result rather than discarding usage. Audio retains input audio/text and output/reasoning detail where supplied. If details are unavailable, settle conservatively at the highest relevant modality rate. Reconciliation never makes uncertain cost disappear.

Predispatch known failure releases reservation. Completed known usage settles actual verified cost and releases excess. Timeout, process death, lost response, cancellation after dispatch or incomplete usage becomes unknown: hold the full reserved amount as encumbered money, terminal state, no automatic retry. Explicit fresh action requires a new reservation. A recovered provider response can reconcile an existing unknown dispatch, never silently re-execute it.

Acceptance: two owners and two worker processes racing for last money cannot both dispatch; restart preserves reservations/unknown; invalid outputs consume budget; same operation key cannot reserve twice; unsupported model/price/missing cap fail closed; cancellation never refunds possibly executed work; no logged prompts/audio/keys.
