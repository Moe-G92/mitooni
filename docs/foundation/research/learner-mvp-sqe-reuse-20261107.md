## Concrete mechanisms worth transferring

**Candidate onboarding and evidence.** SQE `backend/app/routers/guided_learning.py` and `frontend/src/components/onboarding/OnboardingWizard.tsx` collect commitment, persist onboarding and recover recommendation/save errors. `backend/app/services/guided_learning.py::_load_learning_signals` combines actual topic attempts, completed mock evidence and recent tutorial handoffs. `_load_weekly_adherence_snapshot` measures tracked activity against commitment. These are real source mechanisms, but this inspection does not establish a calibrated diagnostic test. Its heuristic weakness weighting is not an IELTS band model.

Receiving proposal: persist exam track, exam date if known, target as a goal, language preference, available study windows and starting-level provenance. IELTS Academic is the governed first pilot. Show unmeasured skills as unmeasured; self-report is not an observed band. Store diagnostic evidence with resource/assessment version, modality, timing, assistance and prior exposure. A short reading drill must not populate speaking/listening/writing scores or an overall band.

**Adaptive plan and accountable changes.** SQE `_guided_learning_execution.py::rebuild_execution_blocks` materializes dated study/review blocks with duration, objectives, priority and rationale. `_guided_learning_replan.py` owns queued jobs, recovery, proposed reviews, apply/defer and journey revisions. Its `deterministic_replan_result` explicitly labels fallback and can recommend review from weak/adherence signals. `agents/planning_agent.py` reads progress and uses persisted planning tools. `frontend/src/lib/guidedJourneyInsights.ts` projects recorded focus, weak topics, commitment and step reasons; it is a useful data-to-interface pattern, not a reason to copy fallback filler text.

Receiving proposal: small server-owned `LearnerEvidence`, `PlanVersion`, `PlanBlock` and `PlanRevision` records; a scheduler bounds choices by time, prerequisites and available licensed resources. AI proposes an evidence-linked plan diff and explanation; the server validates then records its application. Routine next-step adaptation can be automatic within the accepted sequence, while consequential changes remain reviewable/undoable. Do not force a candidate to approve every tutoring turn. Mitooni `app/agents/planner.py` already has the safer read/propose-only shape; extend its validated choices rather than importing SQE’s broad write tools. Missing evidence or provider failure yields an explicit deterministic next activity, never a pretend AI analysis.

**Personalized source tutor.** SQE `services/tutor_context.py::build_tutor_learner_context_snapshot` builds a bounded, owner-scoped current snapshot and SHA signature: current lead/session, progress, practice/mock attempts, stars and tutorial strengths/weaknesses. `agents/tutor_agent.py::build_tutor_agent` injects the latest context each turn, pins learning mode/focus, treats references as quoted data and distinguishes missing grounding from empty results. Tools fetch scoped grounding rather than trust an arbitrary client document. These are the strongest direct reuse patterns.

Receiving proposal: build one versioned context manifest per turn from this candidate’s work/errors, assistance, selected resource anchors, objectives, language and learning mode. AI adapts explanation, scaffolding, examples, pace and the next permitted task from that evidence. Use English exam material within Persian-default/English-option UI. Cite exact safe source anchors; regenerate context from durable state rather than keep accumulating stale snapshots in chat. Support mode and independent assessment use distinct projections. A source instruction cannot override tool authority or reveal an embargoed answer.

**Practice and feedback.** SQE `routers/practice.py::get_next_question` uses a server SQL selector and records exposure; `submit_answer` requires the question to have been served to the owner before reading the key. `agents/tutor_agent.py::_question_answer_is_unlocked` and `tool_get_question_detail` strip correct answer/explanation until a valid attempt. `services/learner_records.py` owner-scopes attempt/note/mock history. Reuse the authorization and answer-release contract, not its SQE MCQ schema. SQE practice submission uses a plain attempt insert; retain Mitooni’s stronger idempotent submission semantics.

Receiving proposal: licensed reading/listening task types require actual item/key mapping, normalization policy and versioned deterministic marking. Writing/speaking require stored candidate work, criteria and evidence-backed formative feedback. Keep feedback, accuracy and teacher-validated band estimates distinct. After feedback, select a targeted repair; only an unseen, appropriately unassisted transfer provides new independent evidence. A tutor may explain the same resource again without relabeling it unseen.

**Mocks and review.** SQE `routers/mock.py` implements owner-scoped session creation, persisted answers/flags/dwell, resume, pause, server timing, terminal submission, results and topic breakdown. The answer projection is separate from the completed result. Reuse this state machine and review linkage. Do not copy SQE section counts, duration, scoring or convert MCQ accuracy into IELTS bands. Mitooni needs actual complete IELTS section resources, matching audio/scripts/keys where applicable and declared timing before a full mock is available. A partial practice route must remain usable without claiming that unavailable full mocks work.

**Progress and repair.** SQE `services/guided_learning.py::load_progress_overview`, `load_step_detail`, tutorial handoff aggregation and `_synthesize_session_handoff` connect learning activity back into the plan. `routers/practice.py` issue reporting provides a material-repair path. Receiving progress should show objective-specific independent evidence, supported practice and time separately; a failed resource can be held and replaced without deleting old attempts. Human coaching is an escalation/additional service, not the substitute for the AI core.

## Smallest receiving architecture

Keep Mo’s account shell and navigation. Complete its existing Today → Practice/Study workspace → Results/Progress loop rather than create another product shell or promote the review panel. The private review tools remain a supporting workflow, not the candidate landing experience.

Use the **existing licensed corpus now** through a server-side `LearningResource` projection. It binds source asset/revision/hash and page/chunk/image locators to objective, difficulty provenance, typed task/key/media dependencies, authority/audience and integrity holds. Whole-source admission remains default; any accepted selected-page exception stays exact and target-bound. A resource can be teachable before every corpus item has been classified, but missing keys/audio/visual dependencies cannot be invented. Existing 42 drafts/admissions and raw page totals are neither a complete learner curriculum nor semantic-completion proof.

Raw corpus storage remains private. The learner projection delivers only the resource content/media authorized for that candidate context, with answer and transcript embargoes where required. SQE’s generated-only serving filter was specific to its product and history: transplanting it unchanged would contradict the present instruction to build with existing licensed IELTS resources. Do not gate the entire MVP on a future generated bank. Preserve provenance, territorial scope and access control while the accountable human team owns clearance; do not invent new rights or reopen a settled business decision as an engineering gate.

Retain `platform/backend/app/providers/agents_runner.py`, `app/workers/tutor_turns.py`, `app/contracts/tutor_runtime.py` and `app/agents/{context,tutor,tools,planner}.py` as the model foundation. Observed controls include explicit model/client injection, bounded turns/tools/output/timeout, validated task context, immutable-work feedback binding, durable dispatch/commit, uncertain-dispatch handling and server-revalidated tools. The SDK provides the agent loop; application code owns storage and approvals ([official Agents guide](https://developers.openai.com/api/docs/guides/agents)). This is preferable to copying SQE’s ChatKit rendering, database schema and broad tools into Mo’s app.

The next provider decision must specify a real authorized model/client, key delivery mechanism, bounded session budget and operator-owned configuration without reading or reusing another venture’s credentials. No bulk synthesis is required to prove the learner loop, and none is authorized by this audit. Development can complete adapter/contracts/recovery paths without a call, but **working AI** requires an authorized bounded real-provider session with persisted output, grounded references and validated tool behavior. A canned response, synthetic runner or typing animation fails that acceptance.

Speaking requires actual microphone/upload/playback, duration limits, retention and server ownership plus a real transcription/feedback path. Existing newly authored narration does not establish alignment of a licensed listening track; listening selection requires its actual resource dependencies. Until operational, mark that activity unavailable with a usable alternative, not a completed or simulated score.
