## Durable entities and versioned contracts

All private records use existing `(product='mitooni',issuer,subject)` ownership and default-deny grants/RLS. Workspace/thread/attempt/turn IDs are server generated; client IDs are idempotency assertions, not authority. Server-only publication/family/policy/entitlement fields never appear in editable patches. Proposed server entitlements are `study:use` for owned journey/workspace/draft/attempt access, `tutor:use` additionally for paid-capable tutoring/planning, and `study:independent` additionally for requesting restricted admission (still subject to exposure/policy checks). Existing `profile:write` or valid identity does not grant these. Only explicit trusted synthetic fixture provisioning adds them in local tests; no production grant or self-enrol rule is implied.

- **VersionBundle:** `packId,packVersion,contentHash,objectiveId,objectiveVersion,rubricVersion,policyVersion,familyRegistryVersion`. A published bundle is immutable; later teacher corrections publish a new version. Old attempts/work remain interpretable. Administrative withdrawal stops new work and follows explicit recovery policy; it never silently rebinds history.
- **Journey:** `id,revision,policyVersion,steps[{stepId,bundleRef,state,reasonEvidenceIds}]`. Bounded server planner projects next permissible steps; model proposals do not directly mutate progress/status.
- **Workspace:** `id,revision,journeyId,stepId,bundleRef,threadId,stage,currentAttemptId,draftRevision,activeTurnId,capabilities`. Unique owned step+bundle resolves to one workspace; another edition is an explicit new binding, not a mutable header selector. Workspace revision tracks structural transitions; draft has its own CAS revision, and turn admission checks both structural revision and the captured workRef. A unique active owner+step+bundle constraint prevents duplicate active contexts; resolving another condition preset cannot silently reuse/convert an existing context. A session restart/reopen reuses persisted state.
- **ContextManifest:** `id,workspaceId,attemptId,conditionsRevision,threadId,protocolVersion,bundleRef,allowedItemIds,inputHash,admissionExposureSequence,contextMode`. Persist server-derived input selection and its hash, never a client hidden-context blob. Help switching creates a new supported manifest/thread and retains the old restricted one; independent admission never continues a supported provider session.
- **Draft:** `id,workspaceId,attemptId,revision,taskId,kind,answers|essay,updatedAt`. `id` is a stable server-generated draft ID, so `workRef.kind="draft"` has an unambiguous reference. Only exact typed response fields writable; no roles, key/explanation, submitted status, elapsed authority or feedback. Keep scope to Reading text/answers and Task2 text, no upload/voice scope.
- **Attempt:** `id,status=open|submitted,bundleRef,taskId,familyId,purpose,originalConditions,currentConditions,conditionsRevision,draftId,draftRevision,responseSnapshotHash?,responseSnapshot?,admissionExposureSequence,assistanceReferences,eligibility{decision,reasons},startedAt,submittedAt?`. Pins/original admission are immutable at OPEN; submission snapshot is assigned once at SUBMIT and then immutable. Current conditions can only downgrade through an explicit learner action, appending history; they cannot upgrade an exposed attempt. A revision is a new child attempt/draft referencing its parent; old content is not overwritten. Supported/same-family/fresh-family developmental/held-out evidence uses remain distinct.
- **Turn:** `id,revision,workspaceId,sequence,inputWorkRevision,bundleRef,intent,inputHash,runnerKind,status,leaseFence,lastEventSequence,privateCandidateBuffer,terminalMessageId,providerDispatchId,error,retryAction,usageReservationId`. `runnerKind=provider|synthetic` is server provenance. Status `queued|running|cancel-requested|canceled|completed|failed|dispatch-unknown`. `completed` requires valid final output+current authority+one durable terminal commit; raw model text/candidates remain private and are never a learner message or draft. Public TurnDTO excludes leaseFence, providerDispatchId, usageReservationId and privateCandidateBuffer; it exposes bounded safe status/error/retry metadata and canonical terminalMessage only after validated publication.
- **Feedback/Evidence:** attributable `actorKind=ai_formative|human_review|deterministic_check`, response/attempt revision, bundle/objective/rubric/policy refs, quoted span refs, observed claim, uncertainty/limitations and correction/supersedes lineage. AI output remains formative. No `marked`/calibrated band state inferred from schema validity.
- **Proposal:** `id,turnId,expectedJourneyRevision,targetStepId,evidenceIds,requestedAction,status=proposed|accepted|rejected,decisionReasons`. Server validator verifies teacher-policy allowlist/prerequisites, owned evidence, current versions/conditions and exposure before one CAS commit. No arbitrary JSON progress snapshot or model-controlled mastery.

## Proposed Mo-facing endpoints and events

Reuse account errors/no-store/Vary/expected-user checks; extend stable codes, never raw SDK/tool exceptions. Every mutation carries UUID `Idempotency-Key`, matching `X-Expected-User-Id`, expected revision and canonical body hash. Operation identity includes owner+route+canonical input+version bundle hash. Replays recheck current authority; stale returned snapshots cannot overwrite newer client revisions.

1. GET `/api/study/journey`: owned plan and bounded capabilities. Before admission this returns objective/step metadata only, not protected stimulus, teaching anchors, private rationale or a fabricated plan. Missing published content is explicit unavailable/empty.
2. POST `/api/study/workspaces/resolve` `{stepId,conditionPreset:"supported"|"independent",expectedJourneyRevision}` **before task/context delivery**: transaction validates membership, published binding and independent eligibility; resolves or creates the owned active workspace, thread/context manifest, OPEN attempt and stable draft ID. Admission freezes policy/conditions/exposure baseline before authorizing initial stimulus release. Server policy derives evidence purpose; conditionPreset is a request, not authority or official exam mode. Unique active owner+step+bundle plus idempotency makes concurrent opens return one context. Same-open-attempt resume checks its conditions and does not mistake its own permitted stimulus delivery for earlier familiarity. Other disallowed post-admission exposure still blocks/downgrades independent completion. Different-condition requests cannot silently reuse a taught/context-rich thread:409 `condition_switch_required` or `assessment_ineligible`. GET `/api/study/workspaces/{id}` reloads that exact owned run/context/draft/attempt/turn; old completed contexts are historical, not fresh independent attempts.
3. PATCH `/api/study/workspaces/{id}/draft` `{expectedDraftRevision,taskId,changes}`: typed CAS save to the server-created current OPEN attempt's draft ID. A submitted draft is not mutable. Return acknowledged draft revision; preserve unsent conflict state. HTTP success only after authoritative commit.
4. POST `/api/study/attempts/{id}/submit` `{expectedWorkspaceRevision,expectedDraftRevision,expectedConditionsRevision}`: recheck conditions/exposure, freeze the already-open attempt's work once and commit its final evidence eligibility/snapshot. It does **not** first admit independent work after the learner has already seen the task. Permitted Reading raw check/rationale release follows submission policy.
5. POST `/api/study/workspaces/{id}/assistance` `{expectedWorkspaceRevision,expectedConditionsRevision,action:"switch_to_supported"}`: explicit learner-only command after the UI confirms the effect, before any hint/teaching-context release. Append assistance/exposure and conditions history, increment revisions, make current attempt permanently supported and bind a supported context without erasing its original restricted-context record. No model tool may invoke this consent. A hint intent by itself cannot switch conditions; return409 `condition_switch_required`. After SUBMIT, do not mutate the old eligibility snapshot; begin a supported child attempt instead.
6. POST `/api/study/workspaces/{id}/attempts` `{expectedWorkspaceRevision,parentAttemptId,conditionPreset:"supported"}`: start a teacher-permitted supported revision after submission, with a new OPEN attempt/draft ID and immutable parent link. Editing and AI feedback/revision proceed against that child; original work/conditions remain attributable. A repeated/same-family revision cannot become fresh independent work. This is a bounded revision command, not a generic attempt factory.
7. POST `/api/study/workspaces/{id}/turns` `{expectedWorkspaceRevision,workRef:{kind:"draft"|"attempt",id,revision},intent,message}` →202 Turn DTO after durable acceptance/reservation. Intent allowlist `explain|hint|feedback|propose_next`; workRef is checked against the workspace and captured server-side, feedback requires an owned frozen submission and allowed supported-review context. Restricted independent work has no live tutor assistance before the explicit switch/submission boundary. One active turn/workspace; competing new turns409, same operation returns the same turn. No client model parameters, continuation IDs, context, tools or hidden messages.
8. GET `/api/study/turns/{id}` without `afterSequence` →200 `{turn,events:[],cursor:lastEventSequence,workspaceRevision,terminalMessage}`: a bounded canonical snapshot, including current safe generation status and `lastEventSequence`. `terminalMessage` is null unless this turn has a committed validated completion; it is the complete canonical validated explanatory message, with feedback/proposal references and source work revision, never reconstructed from SDK deltas. GET with explicit `afterSequence=N` →200 the same current snapshot plus bounded persisted events after N and the returned cursor; consumers deduplicate by sequence. Public event allowlist is `accepted,started,tool_status,completed,failed,canceled,dispatch_unknown`, with safe enumerated statuses only, no model/tool text or arguments. Only an invalid, ahead-of-ledger or expired/compacted **explicit** cursor returns409 `{code:"snapshot_required",snapshotRequired:true,retryAction:"reload_turn_without_cursor"}`; the client then GETs this same route without the parameter and replaces its cursor/status from the snapshot. Missing cursor never409, never reposts generation. Retention/page limits are bounded and documented. Optional SSE later projects this same public ledger, not a second generation path.
9. POST `/api/study/turns/{id}/cancel` `{expectedTurnRevision}` and POST `/api/study/proposals/{id}/accept` `{expectedJourneyRevision}`: current authority/idempotency/server policy. Next-step auto-commit, if later teacher policy allows it, uses the same validator. Model tools cannot bypass consent, conditions or progression validation.

Condition presets do not collapse official delivery format, timing/accommodation policy, service mode or evidence purpose into one field; these remain separately server-resolved versioned conditions. The frontend identified and resolved three initial gaps in this design: draft IDs, pre-delivery independent admission, and explicit irreversible help-switch lifecycle. These are contract clarifications before implementation, not claims of executed tests.

Errors distinguish401 invalid credentials,403 membership/ownership/permission,409 stale revision/binding or assessment-ineligible,422 schema/tool-invalid,429 configured budget/rate exhaustion,503 provider/store/budget-authority unavailable. A provider refusal or invalid output becomes a failed turn with a safe distinct code, never a blank completed lesson. Missing provider configuration fails closed; no silent canned success. UI uses existing session generation/expected identity and retains unsent work on503. Read message text is not an executable action.

## Provider execution, restart and operational failure semantics

Use an explicitly supplied server `AsyncOpenAI` client/model policy with the actual Agents `OpenAIResponsesModel` and bounded `Runner.run_streamed`; no env-file discovery or source default credential. API key helper is not available in this session and no execution/key is needed for this design. Synthetic runner is injected only in the isolated local entry; production composition cannot enable it with a query/header/environment fixture flag.

Before any paid dispatch: active membership/entitlement, immutable content/processing permission, current scope and a transactional token/call reservation must all succeed. Fail closed if authority/reservation unavailable. Configure model/input/output limits, maximum tool calls/SDK turns and wall deadline; do not import source free-tier pricing or invent a subscription. Set client automatic retries explicitly to zero for this boundary; separate safe provider retry decisions from HTTP read retry already ported. RunConfig must disable sensitive tracing by default; log bounded IDs/status/latency/model/version/usage, never essays, anchors, keys, prompts or raw exceptions.

Worker claims a persisted turn with a new fencing token; records dispatch-start before remote execution and checks fence/authority at each tool, event batch and final commit. SDK streams feed bounded private candidate storage; public polling can report only safe generation/tool status while validation is pending. Final validated explanatory assistant item, feedback/proposal references, exposure and terminal turn commit together. Canceled, failed, refused, invalid-output and dispatch-unknown turns publish no buffered model text; their terminalMessage is null. Previously committed messages from other turns remain separate canonical records. A late worker/result cannot replace newer work or a newer turn. A learner edit during generation makes feedback attributable to the captured work revision; it never edits current draft or silently marks it reviewed. Restart reopens acknowledged drafts and committed turns from PostgreSQL; no MemoryStore fallback.

A DB lease expiring before dispatch can be reclaimed. After dispatch began, a crash/timeout may have consumed provider work without a local acknowledgement: mark `dispatch-unknown`, **do not transparently dispatch again**, and do not claim exactly-once provider charging. Reconcile a stored provider response ID only when the actual configured API/storage policy supports retrieval; otherwise expose an interrupted state with explicit user/operator new-attempt recovery. A new generation is a new attributable operation with a link to the uncertain one, not resume-from-text. A known terminal result can be reprojected without another provider call. Existing SDK state/continuation is version/context bound; for this first slice reconstruct from allowed durable thread items and do not enable cross-turn provider continuation until protocol/permission tests pass.

Cancellation is cooperative: persist request, stop new tool effects, call SDK cancel where supported and fence further output commits. It does not imply the provider stopped immediately or refunded usage. Cancellation/disconnect never loses the learner draft. Membership revocation causes new reads/polls403 and prevents tools/final publication; preserve internal audit/usage state without delivering newly forbidden content. Refusal, malformed tool output, missing pack, budget exhaustion and storage corruption have explicit failed/unavailable states; no raw validation input in logs.

## Tool authority and independent-assessment gate

Tools receive server-derived actor/workspace/version/attempt/turn/fence context. Schemas may accept an approved anchor/task/evidence ID, never arbitrary subject, SQL, URL, filesystem path, raw key selector or caller-supplied authority. Reauthorize each model-chosen ID against pinned published scope and action/stage policy before the privileged read. A quoted essay/passage/anchor is untrusted data and cannot introduce instructions or tools. Structured output only constrains shape; validators still check span bounds, citation membership, evidence ownership, allowed next steps and current revision.

The coordinator resolves the product/release tradeoff in favor of actual generated qualitative explanations and feedback, grounded in permitted approved anchors and captured learner work. An approved-ID-only renderer remains an explicitly identified optional safe fallback/test branch, not the tutor product; it never silently turns provider failure into successful production tutoring. Raw SDK prose/candidates stay private until the terminal release gate; no provisional prose is delivered. A bounded candidate DTO is `{kind:"explanation"|"question"|"feedback",text,citations:[{anchorId}],workSpans:[{start,end,quote}],observations:[{criterionId,text,workSpanIndexes}],proposal?}`. The committed public `terminalMessage` envelope is `{id,turnId,workspaceId,kind,text,citations:[{anchorId,label}],workSpans:[{start,end,quote}],observations:[{criterionId,text,workSpanIndexes}],proposalId:null|string,provenance:{actorKind:"ai_formative",runnerKind:"provider"|"synthetic",bundleRef,contextManifestId,workRef:{kind,id,revision}},createdAt}`. Server assigns IDs, resolved citation labels, references and provenance; it publishes no provider IDs, private anchor body, raw candidate, tools, hidden reasoning or usage secrets. Public provenance describes source and scope, not correctness. Initial limits are 6,000 Unicode code points for main text, at most 8 citations, at most 8 quote spans of at most 600 code points each, and at most 8 observations with text at most 1,000 code points each; the serialized public message is at most 32 KiB. `kind` is exactly `explanation|question|feedback`; labels are server-derived and at most 120 code points. Reject oversize candidates before public commit rather than silently truncate references. Citation validation proves approved anchor identity and current authorization, not semantic entailment of every claim. Fields are strictly allowlisted, with no numeric band/scoring/mastery fields, arbitrary HTML, executable actions, client-selected tools or remote URLs. Citations resolve only against the allowed pinned anchor projection; work spans must exactly match the captured work revision; criteria must belong to the pinned rubric. Proposals use the existing deterministic owned-evidence/prerequisite/revision validator. A model-provided identity, action or plan status has no authority.

The output gate first enforces those structural/reference/access checks, then applies bounded prose-policy checks for prohibited scoring claims, unsupported attribution and teacher-policy violations. Invalid structure, embargoed reference, wrong span, refusal, explicitly uncertain/failed validator outcome or a flagged policy violation produces a safe failed turn with no candidate prose released; do not silently publish an invalid candidate after retry exhaustion. Any regeneration is bounded by the same admitted turn budget and documented dispatch semantics, not an unbounded repair loop. Generated qualitative text is inert plain text: escape HTML, do not activate model-written links, and do not interpret quoted learner text as actions or instructions. The public canonical message identifies AI-formative provenance and source work/bundle revisions; this is not human grading or calibrated assessment.

These checks do **not** guarantee semantic truth, perfect band-claim detection or perfect hint-versus-answer restraint in unrestricted prose. Private keys/rationales remain excluded by server-controlled projection before provider context/tool access; that is an enforceable access boundary, not a prompt promise. During supported teaching the model may infer or explain the permitted material and learner work; assistance/exposure is recorded, and no independence claim follows. Independent work has no tutor model/context before explicit supported switch or permitted post-submit review. Teacher policy plus evaluated original fixtures must test whether supported explanations are useful, grounded and appropriately revealing; unknown educational quality is a later validation limitation, not solved by schema validity. The smallest slice uses the real configured source-derived Agents adapter with generated prose, not a static phrase selector; no universal moderation framework is proposed.

The IDs-only alternative was challenged by the coordinator because it narrows the requested BarEx-style tutoring capability. Earlier frontend/learning/security agreement applied to that narrower release design; renewed agreement on this generated-prose contract is required before implementation; frontend and learning reviewers now agree the amended direction, with security final review separately recorded. Private buffering, canonical recovery, immutable binding, access restrictions and durable authority/budget checks remain unchanged.

Separate learner delivery, model grounding and private rationale/key projections. Plan-only tools see approved objectives and minimal progress evidence; they cannot read hidden answer keys or unrestricted notes. A pre-attempt hint is delivered only if the task's assistance policy permits it; it records assistance/exposure. AI cannot mutate or submit learner-owned work, confirm its own mastery or act as an administrator. It may propose an explanation or worked example during supported teaching when teacher policy permits; learner adoption remains an explicit learner draft edit. Canonical history conversion includes current user quote anchoring but excludes obsolete/private/wrong-family context. Context hash/bundle/protocol version persist per turn.

Exposure is durable at task+family+edition and includes stimulus/anchor/rationale/key/model-context delivery, permitted hints and declared prior familiarity. Record before authorizing delivery (conservatively if delivery/render uncertain), including canceled/lost streams. Durable item delivery and model-context release are both exposure events, even if no final assistant reply is committed. Deleting chat, signout, translation, different task ID or fresh thread does not reset exposure. Unknown/incomplete exposure cannot default unseen.

Independent-attempt admission requires eligible author-defined family, clean exposure/assistance conditions, pinned assessment policy and a **new restricted context manifest** with no prior provider response/session/history. Even fresh context cannot rehabilitate a taught family. Independent conditions disable tutor assistance until the relevant submission/release boundary. Post-submission review exposure does not rewrite the prior frozen as-of eligibility snapshot; it affects future family eligibility. If the only toy Reading family has already been taught, independent request is blocked or explicitly supported practice—never a fabricated fresh-test result. Teacher validates family relationships and purpose; coach/model cannot override security/exposure rules. This agrees with the learning contract's T1–T8; evidence/coverage/exposure are not interchangeable.
