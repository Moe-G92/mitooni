## Proposed bounded design

PostgreSQL bytea stores recordings with metadata and jobs in the same transaction. This is preferable to local filesystem for the first teacher beta: no path traversal, orphan-file reconciliation or content/metadata atomicity gap. Bounded cost is explicit: per owner/package maximum 8 recordings and 48 MiB cumulative admitted bytes, per recording 18 MiB; immutable jobs maximum 8, explicit configured cumulative provider-call-unit quota (one reserved unit per job). These are engineering pilot limits. No DB volume claim beyond this pilot. Quotas require server-granted `review:speaking-evaluate`, separate from `review:use`; migration expands allowed permission set but does not grant/activate it automatically. API grants cannot update assignment status, permissions or quota.

Server table `speaking_review_records`: product/issuer/subject/package/target, server UUID recording and job IDs, target/task/rubric versions and hashes, immutable frozen request JSON, exact recording SHA256 and bytea, decoder metadata, state/revision, lease/fence/dispatch ID, candidate/error/result and reserved/settled units. Separate operations unique by owner/package/target/idempotency UUID bind complete body hash, returning only a current-authorized projection. Separate queue contains IDs/issuer/subject only. A per-owner/package budget row stores used bytes/count and reserved/settled units, serialized by the existing owner/package advisory lock. Stored result carries frozen request hash, recording hash and dispatch ID; replay is revalidated against them, not blindly trusted JSON.

Submission body is original raw `audio/wav`, no multipart or new parser dependency. Route `POST /api/content-review/targets/{target}/speaking-recordings` carries bounded headers: `Idempotency-Key`, `X-Expected-User-Id`, `X-Package-Hash`, `X-Target-Hash`, `X-Speaking-Task-Id`, `X-Recording-Sha256`. All field lengths/format checked; caller cannot choose owner, role, filesystem path, URL, rubric text or provider. Server reads within the exact route limit, decodes WAV with evaluator admission, confirms hash and projects frozen task/rubric from configured package. This one request atomically creates recording + submitted attempt + queued job + reservation; no separate unbound upload. Submission rejects non-speaking target/task, unavailable rubric, altered package/target, unsupported/empty WAV and unavailable provider/configuration with safe 4xx/503. Idempotent replay is allowed after current authority and exact-request binding even when quota is now full; changed same-key request conflicts.

`GET /api/content-review/targets/{target}/speaking-recordings` returns safe owned attempt summaries and results (all archived versions remain package/current-authority bound). `GET /api/content-review/targets/{target}/speaking-recordings/{recordingId}/audio` returns authorized complete WAV with private/no-store, Vary Authorization and fixed audio/wav/inline disposition, no filename/path supplied by caller. Small pilot does not support Range; return complete bounded body and no Accept-Ranges, avoiding unauthenticated browser media URLs. Browser fetches bearer-authenticated Blob, creates local object URL for preview and revokes it on account change/unmount; never puts bearer in URL. GET metadata/replay/playback checks active assignment and both permissions, current package/target hashes and immutable byte hash.

Task selection pins one speaking activity/part, not a claimed full-test score. Frozen task text comes from server task projection; private examiner guidance is excluded unless needed by rubric and explicitly approved. Assessment binding uses exact current criterion identifiers, source descriptor identity/version/hash and permitted qualitative rubric. Exposure snapshot records local `revealedAt` as known here and unknown external exposure, plus `recorded_rehearsal`; no blind/independent claim based solely on no local reveal. Provider result covers four criteria or explicit insufficient evidence, with timestamp uncertainty and no numeric score.

Worker queue polling claims under current owner/assignment lock. `claim` validates current package, frozen binding and byte hash, increments fence, grants bounded lease; prepare is no-IO. `dispatch` rechecks authority and fence, persists one server dispatch UUID before IO. A watcher periodically rechecks assignment and cancels if revoked. `complete` rechecks current authority, hash, live lease/fence/dispatch, evaluator strict result and budget; commits result plus terminal state/settlement/dequeue atomically. Before-dispatch failures release reservation. Any timeout/crash/lease loss after marker settles the full reserved unit and terminal `dispatch_unknown`, never automatic redispatch. Definitive completed/refused/invalid outputs also settle the unit. Revoked or invalid content blocks further reads/dispatch/commit; internal terminal cleanup may consume the reservation without revealing content. No automatic second formatting request.

## Independent security correction — private exception boundary

Independent reviewer reproduced a private unhandled exception falling through Starlette's outer fallback, losing private headers and request identity. Coordinator assigned this seam correction. Added `PrivateResponseBoundaryMiddleware` outside other user middleware for private API routes only. It captures complete response start/body privately, forces no-store/Vary Authorization/nosniff/request-id, uses a bounded32MiB bytearray and16KiB/128-header ceiling, then releases a completed response. Endpoint or streaming exceptions before release become a single sanitized500 JSON with requestId. The original exception/body is neither logged nor re-raised. A failed stream's partial marker never reaches the client. Transport failure during final flush is not caught into a second response. Nonprivate behavior passes through unchanged. This is a full-response boundary; private streaming is intentionally not exposed by the current APIs.
