## Decision and source inventory

`supabaseAuth.ts` enables persistSession:true only with an explicitly supplied custom storage implementation, project-specific key and detectSessionInUrl:false. `tabSessionStorage.ts` uses window.sessionStorage only; it accepts exactly the session, user and code-verifier slots for that project. It never accesses localStorage. Preflight access or later storage exceptions fail closed rather than silently falling back to SDK localStorage or memory. Purge removes slots synchronously and falls back to overwriting JSON null when removal fails. Every invalidation revokes prior lease reads/writes/removes, so an old SDK refresh cannot recreate A or delete B. SDK instances are disposed when replaced; dispose alone is explicitly insufficient because the installed SDK permits in-flight fetch completion to write storage.

The optional AuthPort.invalidate hook remains compatible with existing fake/local ports. SessionController invokes it synchronously before deliberate account changes, explicit/peer logout and terminal timeout; null auth events, blocked startup and current initialization failure also purge. An old initialization failure is epoch guarded and cannot invalidate B. Existing capture/assert ownership, refresh-flight and auth-tail guards remain.

Independent security challenge identified that disposing/clearing the SDK before its ordinary signOut would skip server refresh-session revocation. Resolved by retaining one private, generation-accepted JWT revocation handle until queued signout takes and clears it; the adapter invokes `client.auth.admin.signOut(capturedJWT, "local")`, the exact endpoint/scope used inside the installed SDK signOut. No admin secret is needed or used. Local storage is purged first and failure cannot restore it. Actual-SDK tests assert one logout request carries the synthetic old JWT, sees storage already empty, and remains cleared when the response is 503. A separate security reviewer reproduced the installed-SDK logout check. No real provider logout or token revocation has been executed or claimed.

Browser caveat: sessionStorage survives reload and browser restore/duplicate-tab behavior may copy or restore it; no guaranteed tab-lifetime erasure is claimed. If a browser denies both removal and overwrite of an existing slot, software cannot prove physical erasure after later storage recovery; this controller revokes leases and fails closed, and reports storage unavailable. LocalStorage remains used only by the existing signoutBus tombstone/channel fallback; no credentials are stored there by this adapter.
