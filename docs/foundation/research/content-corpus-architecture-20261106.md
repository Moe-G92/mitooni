## Source audit: what the pinned SQE code actually does

References below are relative to the pinned SQE revision. Function names make them reproducible without depending on mutable working files.

**Original table model.** `supabase/migrations/20260222034635_initial_schema.sql` defines `subjects` (line 77), `leads` (91, subject plus target topics/search queries/version), `questions` (112, original/generated type, seed FK, key/explanation/content hash), `study_chunks` (141, source file/index/heading/text/metadata), `entities` and `question_entities` (160), `lead_packs` (182, lead/version/status/harvest/clusters/synthesis/provenance) and `background_jobs` (206). `20260224130425_study_chunk_subjects_v1.sql` adds a private N:M segment-to-subject relation instead of duplicating shared chunks. This is useful separation of source chunks, catalogue concepts, question lineage and generated teaching versions. It is not a ready IELTS schema.

**Source admission is private, not serving ingestion.** Crucially, `supabase/migrations/20260917222845_remove_source_content_from_serving_database.sql` subsequently removes private source bodies/relationships from serving, retains content-free source identities for historical referential integrity, cancels source-dependent generation jobs, strips private provenance and enforces `study_chunks_serving_database_empty CHECK(false)`. The receiving architecture should copy the mature private-authoring separation, not restore the early design of uploading all originals into the active learner database. Reading the initial schema alone would give the wrong conclusion.

**PDF extraction and provenance.** `backend/scripts/ingest_study_chunks.py`: `build_selected_pages` can select the whole file or explicit ranges; `extract_chunks` starts at 445, detects headings, removes running headers, uses an 800-word maximum window fallback, and emits source file/index/heading/content plus page start/end, local PDF path, subject, selected ranges, word count, extractor version and continuation index. `upsert_chunks` at 685 writes batches of 50 on `(source_file,chunk_index)`. `batch_ingest_study_chunks.py` iterates a source manifest, records scan-only PDFs as `ocr_needed`, and attaches N:M subject mappings. This is a useful parser/locator/QA pattern, but no image/audio/ZIP completeness mechanism was established by this code.

**Question ingestion is a separate parser, not PDF chunk synthesis.** `backend/scripts/ingest_questions.py` has format-specific practice and integrated/separated mock parsers, answer resolution, topic→subject mapping, normalized stem/options content hashes, and bounded upsert on `content_hash` (`ingest_questions`, line 539). Reuse the separation of parsed source assessments and teaching segments. Do not transplant regexes, subject mapping, five-option assumptions or legal answer conventions into IELTS.

**Canonical ownership precedes harvest.** `backend/app/engine/harvest.py` defaults to exact canonical `questions.topic` membership in a lead's `target_topics`; it explicitly refuses silently substituting legacy refs or inferred ownership. Entity/FTS expansion is opt-in. `backend/scripts/build_lead_pack.py` marks harvested cluster hints non-authoritative and writes staged pack versions; authoritative clusters belong to later synthesis. A guessed IELTS chapter/skill/topic mapping should likewise stay a proposal until reviewed, rather than being silently promoted because retrieval found it.

**Bounded retrieval is not corpus coverage.** `backend/scripts/synthesize_lead_pack.py:evaluate_study_map_gate` (479) refuses absent maps/priors/chunk hits. `fetch_study_chunks_for_lead` (545) combines direct and mapped subject membership, manual chapter/section priors, entity retrieval and chapter expansion. Constants cap the context at 50 chunks and 6,000 characters per chunk. The source documents an earlier multi-term full-text AND failure that missed relevant chapters. These are meaningful retrieval safeguards, but neither reading a top-K context nor passing its checks establishes full source/roadmap coverage. Keep independent source-coverage and objective-coverage ledgers.

**Synthesis keeps evidence pools typed.** The same synthesis module uses structured outputs, separate question/chunk citation pools, postchecks and `check_verbatim_leakage` (2151). Bad output remains staged. `backend/scripts/batch_synthesize_lead_packs.py:_write_authoritative_submission_artifacts` (350) stores pack/lead/subject/version, question/chunk IDs, prompt SHA-256 and request-body SHA-256; resume rebuilds prepared contexts instead of freely re-harvesting new material. This evidence-binding pattern is reusable. The 80-character overlap scan is only one heuristic, not proof of original authorship or permissible reuse.

**Batch and worker durability are explicit but imperfect.** `backend/app/services/lead_assessment_persistence.py` persists run, per-question, coverage and cheat-sheet artifact records; `20260512135032_lead_assessment_batch_persistence_v1.sql` creates private service-only run/result/coverage tables and provider ID uniqueness. `generated_questions.py` uses compare-and-update queued claims, worker ownership, heartbeats, expiry recovery and attempt counts (`claim_next_generation_job` 953, `heartbeat_generation_job` 1073, `recover_expired_generation_jobs` 1310). `generated_question_worker.py` separates producer/persist/count/failure operations. Review and serving are separate gates, as detailed in the earlier machinery research.

## Concrete defects/limits not to inherit

- `ingest_study_chunks.extract_chunks` emits `extractor_version=3`, while `batch_ingest_study_chunks.is_already_ingested` checks every row for version **2**. Thus the resume predicate disagrees with the producer at this revision. Use an explicit extraction run/version manifest; never infer completeness from count>0 or a stale hardcoded version.
- Replace-source ingestion deletes old rows, then performs multiple independent upserts, then runs QA. An interruption or QA failure can leave partial/invalid replacement contents and changed positional IDs. Use staged immutable extraction revisions and atomic active-pointer adoption after complete QA; preserve prior usable revisions and bindings.
- `batch_synthesize_lead_packs.py` uploads and creates a provider batch before writing authoritative local submission artifacts (679–725). A crash after remote creation can orphan a paid run. Persist a prepared submission intent and all request identities before transport; resume an unknown submission outcome through explicit reconciliation, not blind resubmission.
- The batch result loop rejects unknown IDs and individual HTTP/parse/postcheck errors, but successful item application updates a pack by ID and calls it `tutor_ready`. Its result count/completed provider state cannot alone prove every expected ID occurred exactly once, independent review was completed or the current pack still matches submitted input. Reconcile expected and received IDs first and use expected immutable hashes on landings. Land candidates, never a learner-ready status from provider success alone.
- Assessment result uniqueness `(batch_run_id,custom_id,question_id)` contains a nullable question ID. Ordinary PostgreSQL unique semantics do not deduplicate null-ID errors. The persistence helper also skips rows lacking custom ID/lead ID. Use an unconditional run/item identity for errors and an explicit unbound/quarantined transport-error ledger; otherwise failure evidence can disappear or duplicate during resume.
- `generated_question_worker.py` calls a later heartbeat without checking its return and can mark a run completed even when every candidate was rejected. An expired owner must not land stale work; a terminal job is not an approved bank. Require attempt/fencing token and lease ownership at every write, and evaluate acceptance/coverage separately from processing completion.
- None of the source inspection establishes complete archive extraction, image/OCR fidelity, audio transcription/alignment, per-source processing permission, human IELTS marking validity or calibrated bands. Those are explicit receiving requirements, not SQE capabilities to assume.

## Proposed receiving architecture and ownership

Use one **private local authoring workspace**, with originals outside Git/public assets and content-addressed private derived storage. SQLite is the smallest robust first implementation for inventory/extraction/job metadata on this Mac, with foreign keys, explicit transactions and a single-writer strategy; the existing local PostgreSQL installation can instead host an isolated private authoring database if concurrent workers actually require it. Do not create a universal database abstraction or a hosted corpus now. Keep the active learner database and its fixture lifecycle separate.

`corpus_ingestion` owns source admission, safe discovery/archive traversal, immutable revision/extraction/segment ledger and extraction quality/coverage reports. `corpus_synthesis` owns reviewed objective mapping, synthesis plan, durable batch/item/attempt/output ledger, generation/review states and bank manifests. Both agree the following versioned source-reference contract before writing incompatible stores. Coordinator owns acceptance/publication, processing/budget gates and integration. A source file's presence is not permission for arbitrary remote processing; Arash's confirmed Iranian distribution authority and any distinct processing permission must be represented without inventing legal findings.

Minimal private entities:

1. `assets`: stable opaque asset ID, byte SHA-256, relative private locator, detected/declared MIME, byte size, source/edition/territory/usage provenance, admission state. Keep paths/content out of public projections and default logs.
2. `asset_occurrences` and `container_members`: preserve every discovered path/archive membership even when byte hashes duplicate; member locator, parent hash, compressed/uncompressed sizes, CRC and safe normalized name. Duplicate bytes are not duplicate inventory obligations. Reject traversal, links, nested-archive bombs, oversized counts/ratios and unsupported/corrupt/encrypted members with explicit reasons.
3. `source_revisions` / `extraction_runs`: immutable input hash, extractor name/version/config, modality, run status/timestamps, expected page/frame/time/member extent, quality results and failure/hold. A revision becomes complete only after all declared source extents have a disposition. Reprocessing creates a new run; it never rewrites old cited segments.
4. `segments`: stable segment ID, source revision, modality, text/derived artifact hashes and private locator, exact physical page/bounding region or audio start/end/channel, sequence/heading/continuation, extraction quality and status. Images and scans retain render/region anchors; audio retains original bytes and duration. Transcript generation unavailable means pending transcription, not processed Listening. Preserve question/key/script separation and explicit cross-modal association confidence.
5. `segment_relations`, `objective_mappings`: N:M source/objective/task/skill mapping with evidence, version, proposed/reviewed state and source dependency. Source bank items/passages/audio/key links need their own typed identities; IELTS questions may share one stimulus and recording. No positional chunk index alone serves as durable identity.
6. `coverage_obligations`: every occurrence/member/page/audio range and every roadmap objective has extracted/duplicate/admitted/held/failed/unsupported/synthesized/reviewed disposition as appropriate. Report inventory coverage, extraction quality, curriculum coverage and generated-bank readiness separately. A held source does not disappear from denominators.
7. `authoring_jobs`, `job_attempts`, `batch_runs`, `batch_items`: phase, exact immutable input/source/objective/policy/model/prompt/schema hashes; prepared custom IDs and expected output roles/counts; owner/attempt/fencing/lease; provider state/IDs; submission intent; result/error hashes; cost estimate/actual usage; retry/adjudication links. Persist unknown/malformed/missing results too. Use unique non-null item identities and append-only attempts.
8. `derived_versions`, `reviews`, `adjudications`, `bank_editions`: original teaching, assessment stimuli/items, keys/rubrics and media/transcripts as separate private typed objects; source lineage, family role, validation flags, independent reviewer/teacher pending or decision, exact hashes, supersession/withdrawal and immutable final manifests. Generated public payloads use allowlists, with source references/private scripts/keys absent.

Shared source reference minimum: `schema_version`, `asset_id`, `asset_sha256`, `source_revision_id`, `extraction_run_id`, `segment_id`, `segment_sha256`, `modality`, `locator` (page/region/time/member), `extractor_version`, `quality_state`, `admission_policy_revision`, `permitted_processing_scope`. Synthesis verifies these against the private ledger and refuses drift, dangling IDs or held/failed segments. A batch is pinned to a frozen source snapshot, not a mutable inventory path.

## Pipeline and provider boundary

The smallest stages are: full discovery/admission → modality-specific extraction and associations → complete coverage reconciliation → teacher-reviewable skill/objective mapping → original pack/bank synthesis plan → deterministic originality/schema/source checks → independent blind execution → controlled source-aware diagnosis → independent educational/teacher review and adjudication → evaluated immutable candidate edition → guarded generated-only promotion. A private 24-unit edition can be one reviewed slice while full-corpus obligations remain visible. It must not become the hardcoded bank capacity or a reason to exclude the remainder of supplied resources.

Implement a provider-neutral request/result protocol around existing producer interfaces, not SDK calls inside extraction. A deterministic stub validates planning and recovery. An eventual OpenAI or other approved batch adapter supplies prepare/submit/status/download/cancel and normalized usage/result/error records; model names, API behavior and prices must be verified against current official documentation at implementation time. Historical SQE transport (`backend/app/services/anthropic_batches.py`) is a small lazy-import adapter pattern, not current pricing/API authority. No provider transport may execute before explicit processing authority, provider/model selection and an authorized budget cap. Never use an undisclosed paid fallback.

Before submit, freeze request IDs/hashes and reserve approved budget in a transaction; persist submission intent. Remote create is an external effect with uncertain outcomes on timeout: represent `submission_unknown`, reconcile against recorded transport evidence and require operator resolution if the provider cannot offer safe idempotency. Do not assert exactly-once remote semantics without provider evidence. Persist returned batch IDs immediately. Resume downloads are idempotent and reconcile all expected IDs, duplicates, missing rows and error files before candidate acceptance. Retry only failed/missing obligations under a new attempt, preserving original outcomes and completed work. Late stale attempts cannot change current state.

Partial successful synthesis may produce isolated **candidates** while other obligations remain pending; it cannot certify complete bank coverage or learner eligibility. No result parser sets teacher-approved. Deterministic failures cannot be waived by generic model approval. Source conflicts need evidenced adjudication; coverage gaps remain enumerated, not hidden by removal. Model-context permission and learner-delivery permission are separate from local processing and private teacher review.

## Minimum receiving acceptance evidence

- Discover every PDF/audio/image/archive occurrence and member under authorized roots. Reconcile counts/hashes and explicit held/failed reasons; inventory and extraction denominator remain stable under duplicate discovery. Prevent symlink escape, ZIP traversal/bombs, ambiguous/corrupt inputs and source changes during ingest.
- For synthetic mixed corpora, compare sampled extracted text/render regions, timing/transcript anchors and source associations to actual original bytes. Scan-only PDFs, image diagrams and unsupported audio generate explicit obligations; none counts complete because metadata exists.
- Kill extraction between batches, rerun and change extractor configuration. No partial revision is adopted; prior cited revisions remain readable; identical extraction is idempotent; changed input/config creates a new immutable run. Verify coverage and content hashes, not row count alone.
- Change source bytes or segment mapping after synthesis preparation. Submit/land refuses stale hashes. Objective mapping suggestions and retrieval top-K hits cannot advance reviewed coverage without evidence.
- Simulate crash before/after remote acceptance, timeout with unknown outcome, duplicate/out-of-order/unknown/missing outputs, null/unbound errors, partial provider completion and expired worker takeover. All obligations and adverse results survive; budget cannot be double-spent; stale fencing token cannot land; a missing report never passes.
- Challenge originality against the entire admitted source corpus and generated bank, including stimulus/key/script and semantic family overlap. Deterministic overlap screening plus independent review is evidence, not a blanket guarantee. Preserve both detected findings and reasoned item-level dispositions.
- Verify teacher-pending/held/rejected/unsupported-media items never appear learner-ready. Reviewers cannot approve their own authored versions; exposed sessions cannot take fresh blind tasks; disagreement retains original evidence and blocks affected release only.
- Promote a synthetic generated-only edition through actual server projection and selector checks. Source corpus, provenance, keys and Listening scripts stay private; attempts retain seen versions; withdrawal/rollback preserve history. Four-skill media/runtime gaps remain explicit until real delivery tests exist.
