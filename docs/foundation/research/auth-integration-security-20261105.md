## Required contract decisions and falsifiable checks

1. **Name each authority.** Preserve S1 identity DTO separately, or explicitly version/redefine `/api/me` as the authenticated Mitooni bootstrap/profile endpoint; frontend and backend must choose the same contract. A server-trusted constant/config identifies product `mitooni`; caller headers/query/body cannot choose it. Membership repository maps verified auth subject plus product to active/pending/suspended/revoked state and server-owned entitlements. No email-match, signup metadata, plan name or token existence implicitly grants membership. If new signup enrollment is intended, specify a separate authorized, atomic, idempotent provisioning rule; do not accidentally implement it as a GET side effect. Tests: valid BarEx identity/no Mitooni membership cannot GET/PATCH Mitooni profile; injected product/role/owner/plan claims ignored or rejected; revoked member rejected on the next protected operation; provider/repository error never becomes an empty/default active member. No shared raw record transfer.
2. **Bound profile PATCH.** Explicit DTO with unknown fields forbidden, bounded display name, supported locale/theme, target bands (0–9 half steps), valid date/hours, notification booleans and clearly defined merge/null semantics. Never editable through profile: auth subject/email verification, owner/product, membership/role/coach, entitlement/plan, score/current assessed level, submitted/assessment state. Recovery/login email changes belong to verified auth flow, not profile persistence. Accommodation preference may be user editable for practice only if no implication of official entitlement; assessed/timed policies snapshot independently. Onboarding completion is derived after required validated fields or a dedicated command; cannot silently activate product access. Atomic validation means no partial changes on rejected nested fields. Tests include mass assignment, nested extra keys, null/absent, large strings, nonfinite hours, invalid enum/date/band, replay/concurrent version conflicts and no-store on both success and errors.
3. **Account-epoch ownership.** Auth transition advances a generation synchronously, clears visible protected data, cancels requests and prevents old responses/mutation callbacks from committing. Requests capture product, expected subject and epoch; recheck before send, after refresh and before decoding/committing. Keys are identity/product scoped or a per-identity QueryClient is destroyed; mutation variables/forms are remounted or cleared. Abort is best effort, not proof of prevention at the server. Server authorizes each request based on its presented identity; account A data is never submitted with newly resolved B token. Tests: hold A GET/PATCH/refresh/blob response, switch to B/logout, release A response; B DOM/cache/forms/outbox remain B-only. Failed remote sign-out still locks local UI and prevents further protected writes; no automatic retry later under another identity. Cross-tab sign-out/account change follows same rules. Unsent work must not be silently reassigned or discarded by a new account.
4. **Explicit lifecycle states.** Auth initializing, signed out, confirmation required, identity valid/product access missing, profile/onboarding incomplete, ready, unavailable and session expired are distinct. Preserve Mo layout with focused recovery; do not redirect a 503 outage into a sign-in loop or retry 403 membership denial as token expiry. Missing browser config creates no SDK request and fails closed; missing backend config/repository gives unavailable. Identity-only `/me` cannot be cast into full profile with fabricated defaults. No synthetic signed-in account in ordinary startup. Tests cover each state and required protected-render denial, not just final success.
5. **Transport safety.** Adapt Bearer transport and structured errors to Mo, not cookies plus a second fallback. Only positive configured API/auth origins are used; no source domain default, no tokens in URLs/logs, redirects or other-origin fetches. `credentials:omit` for bearer BFF unless a separately reviewed cookie requirement exists; exact CORS/origin policy. One refresh can recover a read for the same expected subject/epoch; writes require explicit safe semantics/idempotency and unchanged operation ID. A 401 path must reject before any server write. Generic errors must not echo tokens/provider raw HTML. Runtime schema validation rejects identity/profile/error mismatch. Redirect `next` is restricted to canonical same-product relative allowlisted routes, rejecting `//`, schemes, backslashes/control characters and auth-loop routes. Test every bypass spelling as a unit table and at least one browser journey.
6. **Mock isolation is a release property.** An explicit development/test entry can retain Mo's synthetic reference experience. Ordinary production build cannot import/serve mocks, seed/scoring fixtures, `/dev/reset` controls, arbitrary-auth handlers or a mock service worker. Existing registered worker scope/cache must be handled during cutover; same-origin service workers survive a new bundle. No generic unregister of unrelated apps; target the known prototype worker/scope in a deliberate migration/reset procedure. Test ordinary build output/public files and a browser previously using the mock worker, plus fresh production startup with `VITE_USE_MOCKS` unset/true/query/storage toggles: no fixture login/data and no source/provider calls on invalid config. Test entries fail build if accidentally selected for release.
7. **Retain least-data boundaries.** Auth-only browser SDK; non-auth profile/bootstrap through BFF. Server DTOs return only Mo's necessary profile/entitlement fields, no cross-product source profiles, messages, raw response blobs or metadata. Role/coach features remain absent until assigned-resource controls exist. Server service-role clients bypass RLS, so repository queries must include trusted product/subject predicates; eventual schema/grants/RLS tests are separate real-store gates. Fake repository tests establish contract behavior only. No source production config, env, account store, content or coaching record is copied.
